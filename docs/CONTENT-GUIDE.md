# Content Guide

Schemas, ingestion scripts, authoring rules, licensing and attribution for
every content type Clutch ships: the Highway Code, the National Standard
syllabus, facts, questions and road signs (Know Your Traffic Signs).

## Principles

Content is data, not code: JSON + Markdown under `content/uk/`, validated
against Zod schemas in `src/content/schemas/`. `npm run validate:content`
must exit 0 and runs inside `npm test`.

## Schemas

Zod schemas live under `src/content/schemas/`, one file per content type,
re-exported from `index.ts`:

- `pack.ts` — `PackSchema`, for `pack.json`.
- `highwayCode.ts` — `RuleSchema`, `SectionSchema` and
  `HighwayCodeIndexSchema`, for `content/uk/highway-code/`.
- `facts.ts` — `FactSchema` and `FactsFileSchema`, for `facts.json`.
- `syllabus.ts` — `SyllabusSchema`, for `content/uk/syllabus.json`.
- `signs.ts` — `SignSchema`, `ShapeRulesFileSchema`, `HooksFileSchema`,
  `SignSelectionFileSchema` and `AttributionManifestSchema`, for
  `content/uk/signs/`.

`content/uk/highway-code/`, `content/uk/syllabus.json`,
`content/uk/signs/signs.json` and `content/uk/signs/attribution.json` are
generated by the ingestion scripts below and are never hand-edited;
`content/uk/signs/selection.json`, `shape-rules.json` and `hooks.json` are
hand-authored inputs to them.

## Ingestion

Three scripts fetch gov.uk, each run manually, once, against the live API —
never from a test, from `npm test`/`npm run build`, or from CI:

- `scripts/ingest-highway-code.ts` — `npm run ingest:highway-code` — fetches
  the Highway Code landing page and all section pages, writing
  `content/uk/highway-code/index.json` and
  `content/uk/highway-code/sections/*.json`.
- `scripts/ingest-national-standard.ts` — `npm run ingest:national-standard`
  — fetches the National Standard for Driving Cars and Light Vans landing
  page and its role pages, writing `content/uk/syllabus.json`.
- `scripts/ingest-signs.ts` — `npm run ingest:signs` — fetches every Know
  Your Traffic Signs chapter (plus one extra "the signing system" page),
  scans each rendered page for licence exceptions, selects and classifies
  the sign set, and writes `content/uk/signs/signs.json`,
  `content/uk/signs/attribution.json` (and a byte-identical copy at
  `public/signs/attribution.json`) plus every chosen picture under
  `public/signs/<family>/`.

All three reach gov.uk only through `scripts/lib/govuk.ts` — the sole
module allowed to call `fetch` outside `src/features/me/Attribution.tsx`
(same-origin `ATTRIBUTION.md` only) and the e2e helpers (which only probe a
local port to prove it is down). Politeness, as actually coded there:

- **Delay** — 600 ms (`delayMs`) waited before every real request; skipped
  entirely on a cache hit.
- **User-Agent** — `clutch-ingest/0.1 (+https://linkabot.github.io/clutch/)`,
  sent on every request.
- **Retries/backoff** — up to 3 retries (`retries`) on a 429 or 5xx
  response, backing off `2000 ms / 4000 ms / 8000 ms` between attempts.
- **Sequential only** — one request at a time, never in parallel, so the
  delay is an honest gap between real requests to gov.uk.

**Cache directories:** each script passes its own `cacheDir` —
`content/.cache/highway-code/`, `content/.cache/national-standard/` and
`content/.cache/kyts/` — where `fetchContentApi`/`fetchCachedText`/
`fetchCachedBytes` write every raw response and read from there on a later
run instead of re-fetching. All three directories are listed in
`.gitignore` and must never be committed. When
`process.env.CLUTCH_OFFLINE === '1'`, a cache miss throws instead of ever
reaching the network — `npm run verify:signs` forces this at the top of
`scripts/verify-signs.ts`, before any call that might reach the network.

**Rule:** ingestion runs only manually against the live API and its JSON
output is committed as content; it is never invoked from tests or CI. The
all-green gate proves this: it runs one grep scoped to `src` for any file
that both calls `fetch(` and mentions `gov.uk` —
`grep -rlE 'fetch\(' src | xargs -r grep -lE 'gov\.uk'` — and fails if that
count is nonzero. `scripts/` itself is never scanned by this gate, since
the ingestion scripts living there are the ones allowed to fetch gov.uk at
all.

## Road signs (Know Your Traffic Signs)

Sign pictures and captions come from Know Your Traffic Signs (KYTS), DfT's
GOV.UK publication, across 7 chapters, each mapped to one Clutch family:

| Chapter slug                                    | Family        |
| ----------------------------------------------- | ------------- |
| `warning-signs`                                 | `warning`     |
| `regulatory-signs`                              | `orders`      |
| `speed-limit-signs`                             | `orders`      |
| `motorway-signs-signals-and-road-markings`      | `motorway`    |
| `direction-signs-on-all-purpose-roads`          | `direction`   |
| `information-signs`                             | `information` |
| `signs-for-road-works-and-temporary-situations` | `road-works`  |

**Licence.** Every chapter is licensed under the Open Government Licence
v3.0, `© Crown copyright 2023`. `scripts/lib/kyts-licence.ts`'s
`licenceProblems` scans each chapter's RENDERED page (not the Content API
body) and requires the exact line `CROWN_LINE` (`© Crown copyright 2023`),
the exact sentence `OGL_SENTENCE` ("This publication is licensed under the
terms of the Open Government Licence v3.0 except where otherwise stated.")
and the exact sentence `THIRD_PARTY_SENTENCE` ("Where we have identified
any third party copyright information you will need to obtain permission
from the copyright holders concerned.") on every page's `<main>`, flagging
any other copyright/"except" sentence and any kept sentence absent from
some other page. `npm run ingest:signs` fails the whole run on any problem
this reports.

**Selection.** `content/uk/signs/selection.json` holds `chapters[]`,
`families[]`, `r2CaptionPrefixes[]`, `r3PlateFiles[]`,
`r5SubHeadingPrefixes[]`, `r8NamedParagraphCaptions[]`,
`allowLists` (`motorway`/`direction`/`information`/`road-works`),
`expectedCounts` (one count per family), `expectedTotal` and
`thirdPartyMarks[]` (see **Third-party emblems** below).
`scripts/lib/kyts-select.ts` applies its rules **R1–R8**, R8 first:

- **R1** — drop a picture with an empty caption.
- **R2** — drop a picture whose caption starts with one of
  `r2CaptionPrefixes`.
- **R3** — drop a picture whose file is listed in `r3PlateFiles`.
- **R4** — drop a duplicate file name or caption.
- **R5** — drop a picture under a motorway sub-heading listed in
  `r5SubHeadingPrefixes`.
- **R6** — content-safety and size: `svgIsSafe` fails an SVG containing a
  `<script`, an `on…=` event attribute, or a remote `href`/`xlink:href`;
  the file must also be 150 KiB (`153_600` bytes) or smaller, `<=`, so a
  file of exactly 153,600 bytes is kept.
- **R7** — every file listed in `allowLists` must pass, or the run throws.
- **R8** — a paragraph-caption override for STOP and GIVE WAY, applied
  before R1–R5: `stop-sign-and-road-marking.svg` and
  `give-way-road-marking.svg` take their name/meaning from the KYTS
  paragraph immediately before their `<figure>` (never the figcaption),
  whose exact opening text is `r8NamedParagraphCaptions`' `paragraphPrefix`
  — "The ‘STOP’ sign and road markings:" and "The ‘GIVE WAY’ sign and road
  markings:".

The committed set is **195 signs**: warning 66, orders 54, motorway 22,
direction 25, information 12, road-works 16 — exactly
`selection.json`'s `expectedCounts`/`expectedTotal`.

**Shape and colour rules.** `content/uk/signs/shape-rules.json` holds
`rules[]` (ids C1–C9; C7 alone uses an `outcomes` object keyed
`C7-green`/`C7-white`/`C7-green-white` instead of its own
shape/colours/sentences, for direction and information signs on primary vs
non-primary routes), `shapeSentences` (`circle`/`triangle`/`rectangle`),
`exceptionsSentence` and `decoderPairs[]` (7 rows: 6 real shape/colour
pairs — circle/red, circle/blue, triangle/red, rectangle/blue,
rectangle/green, rectangle/white, each with a title, a body and 3 example
sign file names — plus 1 catch-all row with `shape`/`colour`/`title` all
`null`). `exceptionsSentence`, quoted exactly as the file holds it:

> There are a few exceptions to the shape and colour rules, to give
> certain signs greater prominence. Examples are the ‘STOP’ and ‘GIVE WAY’
> signs.

**Memory hooks.** `content/uk/signs/hooks.json` holds 16 hooks: 7 keyed by
`appliesTo.rules` (a shape/colour rule id, e.g. `rule-triangle-red`), 6
keyed by `appliesTo.family` (one family, e.g. `family-warning`) and 3 keyed
by `appliesTo.signIds` (e.g. `sign-speed-max-min`). `hookFor()` in
`src/content/signs.ts` implements the display rule: on a sign's own page,
only its own hook shows (else nothing); on the quiz sheet, a sign's own
hook shows first, else its rule's hook, else its family's hook, else
nothing.

**Captions copied verbatim.** A sign's `name`/`meaning` is its KYTS caption
(or, for STOP/GIVE WAY, its R8 paragraph text), copied exactly — never
paraphrased and never typed from memory.

**Pictures shipped byte-for-byte.** Every kept SVG is committed unaltered
under `public/signs/<family>/`. `.gitattributes` marks the whole tree
binary (`public/signs/** -text`), so git never normalises its line
endings, and `.prettierignore` excludes `public/signs` (and
`content/uk/signs/signs.json`, `content/uk/signs/attribution.json`) so
Prettier never reformats them. Every shipped file is 150 KiB or smaller
(R6, above) and passes `svgIsSafe`'s content-safety test.

**Attribution manifest.** `content/uk/signs/attribution.json` and its
byte-identical copy `public/signs/attribution.json` each list all 195
shipped pictures, one entry per file: `file`, `sourceUrl`, `chapterUrl`,
`bytes`, `sha256` (64 hex characters), `licence` and `copyright`. The
pictures listed in `thirdPartyMarks` also carry `"thirdPartyMark": true`.

**Third-party emblems.** The licence scan reads text, so it cannot see an
organisation's emblem, logo or trade mark drawn inside a picture, and the
Open Government Licence does not cover trade marks or third-party rights
the publisher is not authorised to license. Before a sign is added, look
at its picture. If it shows one, as the National Trust, English Heritage
and England tourist-destination symbols do, list it in `selection.json`'s
`thirdPartyMarks` (`{ family, file }`) and in `scripts/verify-signs.ts`'s
`EXPECTED_THIRD_PARTY_MARKS`. `npm run ingest:signs` then marks it
`"thirdPartyMark": true` in `signs.json` and both attribution manifests,
and throws if a listed file is not a selected sign. `npm run verify:signs`
counts any difference from its own list as `thirdPartyMismatch`. The sign
page shows a third-party notice under the attribution line, and
`public/ATTRIBUTION.md` names the file.

**`SignSchema`'s fields** (`src/content/schemas/signs.ts`): `id` (a
family-prefixed regex), `name`, `meaning`, `family` (`warning` / `orders` /
`motorway` / `direction` / `information` / `road-works`), `shape`
(`triangle` / `circle` / `rectangle` / `other`), `colours[]` (`red` /
`blue` / `green` / `white`), `rule` (`C1`…`C6`, `C7-green`, `C7-white`,
`C7-green-white`, `C8`, `C9`), `hookId` (string or `null`), `image` (a
`signs/<family>/….svg` regex), `refs[]` (at least one
`{ kind: 'section', slug }`), `licence` (the literal string
`Open Government Licence v3.0`), `thirdPartyMark` (the literal `true`,
only on a sign listed in `thirdPartyMarks`) and `source`
(`chapterSlug`/`chapterUrl`/`imageUrl`/`subHeading`). The top-level
`signs.json` file also carries `publication`
(`title`/`url`/`publicUpdatedAt`), a `licence` block
(`name`/`url`/`copyright`/`statement`/`thirdPartyStatement`) and
`signingSystemText`.

**The Decoder's text** (Learn ▸ Shape & Colour Decoder) comes from
`content/uk/signs/shape-rules.json` and `content/uk/signs/hooks.json`
through `getShapeRules()`/`getHooks()` in `src/content/signs.ts`, paired by
`pairContent()` in the Decoder's own `decoder.ts`.

**How to refresh:** run `npm run ingest:signs` against the live API, then
`npm run verify:signs` — an offline re-derivation from
`content/.cache/kyts/` that prints one summary line (`verify: signs=<n>
warning=<n> orders=<n> motorway=<n> direction=<n> information=<n>
road-works=<n> files=<n> bytesKiB=<x> maxKiB=<x> captionMismatch=<n>
hashMismatch=<n> licenceProblems=<n> classMismatch=<n> orphanFiles=<n>
provenanceMismatch=<n> thirdPartyMismatch=<n>`) and passes only when the
sign and file counts are exactly 195 with the right family split and every
one of `captionMismatch`/`hashMismatch`/`licenceProblems`/`classMismatch`/
`orphanFiles`/`provenanceMismatch`/`thirdPartyMismatch` is 0. A count,
caption or licence difference fails the run and becomes a plan amendment —
the script never adapts to match a changed source.

## Highway Code re-parse

`scripts/lib/highway-code-build.ts`'s `PARSE_FLAGS` names exactly three
flags, all default `true`:

- **`repairHrefs`** — repairs 5 malformed-href patterns (a zero-width
  space before `#rule`, a missing leading slash, a bare `www.gov.uk/…`)
  before the normal href rewrite; off reproduces the pre-flag output
  byte-for-byte.
- **`figcaptionLinks`** — pairs a bare `<img>` or an image-only `<p>` with
  an immediately following `<figcaption>`, using the figcaption's text as
  the diagram link's label; also changes the link's visible text to
  "↗ `<label>` (diagram, online)" (or the bare "↗ Diagram (online)" when
  there is no label). Off, the link reads "Diagram (online): `<label>`".
- **`interludes`** — a kept run of top-level siblings between or after
  rule headings is sanitised and stored as the section's `interludes[]`
  (`{ beforeRuleId, html }` entries); off, the `Section` object carries no
  `interludes` key at all.

**Named sanitiser cases** (`scripts/lib/highway-code-parse.ts`):
`dropEntirely()` (removes the whole subtree — script/style/noscript/
template/iframe/object/embed), `imageReplacement()` (replaces an `<img>`
with the labelled online-only link above, or plain text if its `src` is
unsafe), `unwrapFigureParts()` and `unwrapKeepingChildren()` (both keep the
inner HTML unchanged, for a `<figure>`/`<figcaption>` that reached the
fallback, or any other unknown/disallowed tag).

`CLUTCH_OFFLINE=1 npm run ingest:highway-code` re-parses entirely from
`content/.cache/highway-code/`: a cache miss throws instead of reaching the
network, and the committed `fetchedAt` timestamp is kept rather than
stamped with the current time.

`npm run compare:highway-code` rebuilds the Highway Code in memory and
diffs it against the committed JSON. `--flags off|on|<name>` toggles every
`PARSE_FLAGS` entry off, on, or just the one named flag; `--list` prints
one `diff <file> <json-path>` line per differing path; `--dump <dir>`
writes the in-memory build to `<dir>`; `--attribute` builds once per flag
to say which flag explains each differing path. Its own summary line:
`compare: files=<n> identical=<n> differing=<n> paths=<n> malformed=<n>`.

## Pack

`pack.json` = `{ region: "GB", version, attribution[] }`.

## Facts

`facts.json` is the ONLY permitted source of numbers in questions. Each
fact cites its Highway Code rule or gov.uk source.

Every fact carries a `verification.method`, one of:

- `quote-in-rule` — the fact's `quote` is a verbatim substring of the
  cited rule's (or section's) ingested text.
- `pending-human` — a number copied from an official source that still
  needs a human check against the original chart or page
  (`verification.against`).
- `human-vs-official-chart` — a `pending-human` fact a human has since
  confirmed against the official chart, recording who (`by`) and when
  (`on`).

`quote` must be a verbatim substring of the cited rule's ingested text —
never paraphrased and never typed from memory. It is copied from the
committed section JSON: `htmlToText` of the cited rule's `html`, or of the
cited annex's `bodyHtml`. When a fact's `value` is a number, the quote
must also name that value itself (the digit, or an accepted word form
such as "two" or "doubled") — a table row's label alone is not enough. A
number that cannot meet this is dropped, never adjusted to fit.

Seeded fact ids (Rules 124, 126, 226, 100 and Annex 6):
`speed-limit-built-up-default`, `speed-limit-built-up-wales`,
`speed-limit-cars-single-carriageway`, `speed-limit-cars-dual-carriageway`,
`speed-limit-cars-motorway`, `following-gap-seconds`,
`following-gap-wet-multiplier`, `following-gap-icy-multiplier`,
`tunnel-stop-gap-metres`, `fog-visibility-headlights-metres`,
`child-restraint-height-metres`, `seat-belt-child-age`,
`tyre-tread-minimum-mm`. Stopping-distance facts are seeded separately and
stay `pending-human` until a human confirms them against the official
chart.

## Questions

Field list: `id`, `category` (one of the 14 DVSA topics), `stem`,
`options[]` with exactly one correct, `explanation`, `refs[]` that must
resolve, `tags[]`, `difficulty`, optional `syllabus[]`, optional `image`.

## Attribution

`public/ATTRIBUTION.md` is shipped and shown on Me. Highway Code and
National Standard text carry "Contains public sector information licensed
under the Open Government Licence v3.0." The Know Your Traffic Signs
section adds its own line: "Sign pictures and sign wording: Know Your
Traffic Signs, Department for Transport, © Crown copyright 2023. Licensed
under the Open Government Licence v3.0 … The pictures are reproduced
unaltered from https://www.gov.uk/government/publications/know-your-traffic-signs.
Every picture and its source address is listed in
`signs/attribution.json`." — pointing at the per-picture attribution
manifest described above. That section also quotes gov.uk's third-party
sentence and names the three pictures marked `thirdPartyMark`.

## Never

No pasting from commercial sources. No video fetching. Links out only as
clearly online-only extras.

## Regional differences

State regional differences explicitly rather than averaging them — for
example the Scotland drink-drive limit and the Wales 20 mph default.

## Known limitations

- **Highway Code diagrams are still online-only links.** Every `<img>` in
  the ingested Highway Code HTML is stripped and replaced with a clearly
  marked online-only link ("↗ `<caption>` (diagram, online)"); the
  original `{ src, alt }` is recorded in the rule's `images[]` array
  (`RuleSchema`) for a later phase to fetch and precache. KYTS sign
  pictures, by contrast, ARE shipped and precached — see § Road signs,
  above.
- **Non-Highway-Code gov.uk facts are deferred.** Numbers that live on other
  gov.uk pages — drink-drive limits (England/Wales vs Scotland), the
  new-driver 6-points/2-years rule, the phone-use penalty, supervising-driver
  ages, and the theory-test format — are not in `facts.json` yet. They wait
  until their source pages are ingested through the same polite
  `scripts/lib/govuk.ts` path, above, so their quotes can be verified
  mechanically like every other fact, rather than typed from memory.
